## 2. Улучшенный поиск и обработка обложек (High-Res Cover Art) 🎨
- [x] **Каскадный поиск Ultra-HD обложек:** *(Реализовано в `core/coverart.py`)*
  - Собираются кандидаты из Cover Art Archive, Last.fm, iTunes и Deezer, затем ранжируются **по реально достижимому разрешению**, а не по порядку ответа. Раньше обложка Last.fm на 300px перебивала iTunes на 1000px.
  - Поиск официальной альбомной обложки даже при скачивании по прямой ссылке на YouTube (замена превью видео на студийный арт).
- [x] **Политика разрешения по качеству аудио:** *(Реализовано)*
  - **FLAC → 1400×1400** — нативный мастер Deezer.
  - **MP3 → 768×768** — серверный ресайз без интерполяции.
  - Размер выбирается по **фактическому контейнеру** файла, а не по запрошенному качеству: если FLAC не нашлось и пайплайн откатился на MP3, обложка 1400px туда не попадёт.
  - Ресайз делается **подстановкой размера в URL** у CDN, которые это умеют (Deezer, iTunes, Cover Art Archive), а не растягиванием картинки.
  - Апскейл ограничен: обложка 500px не растягивается в 1400px, но 1200 → 1400 допускается.
- [x] **Умная обработка YouTube Thumbnail:** *(Реализовано)*
  - Автоматический выбор максимального разрешения (`maxresdefault.jpg` -> `hqdefault.jpg`).
  - Умный кроп соотношения 16:9 в квадрат 1:1 по центру без черных полос (letterboxing).
- [x] **Проверка реальных пикселей вместо доверия URL:** *(Реализовано)*
  - Собственный парсер заголовков JPEG / PNG / GIF / WebP (`probe_image_size`) — CDN регулярно отдаёт не то, что заявлено в ссылке (SoundCloud молча отдаёт 500×500, Spotify не поддерживает `?size=`).
- [x] **Исправлен Cover Art Archive:** был жёсткий `front-500` в самом верху каскада — то есть минимальный размер побеждал все 1000px-источники. Теперь `front-1200` с подбором наименьшего достаточного размера.
- [ ] **Сохранение обложки отдельным файлом:**
  - Опция сохранения `cover.jpg` / `folder.jpg` рядом с треками для плееров и медиасерверов (Plex, Navidrome, Jellyfin).

## 3. Режим «Оригинал без перекодирования» (Native Audio Stream) 🎚️
- [ ] **Сохранение исходных контейнеров (`--format original` / `-f opus|m4a|mp3|flac`):**
  - Для YouTube/SoundCloud: прямое извлечение исходного потока Opus (~160 kbps) или AAC (~128 kbps) без пережатия ffmpeg.
  - Защита от **generational loss** (потери качества при повторном lossy-to-lossy сжатии Opus -> MP3).
  - Экономия ресурсов процессора и ускорение скачивания треков.
- [ ] **Нативное тегирование оригинальных контейнеров:**
  - Полноценная запись метаданных и вшивание обложек в `.opus` (через Mutagen OggOpus) и `.m4a` (через Mutagen MP4).

- [ ] **Караоке `.lrc` файлы:**
  - Сохранение синхронизированных субтитров рядом с аудиофайлом (`Artist - Title.lrc`) для плееров с караоке (Poweramp, Retro Music, AIMP, Symfonium).
- [ ] **Вшивание в теги:**
  - ID3v2 (MP3): фреймы `USLT` (Unsynchronized lyrics) и `SYLT` (Synchronized lyrics).
  - FLAC / Vorbis Comments: поля `LYRICS` и `UNSYNCEDLYRICS`.
  - MP4 / M4A: тег `\xa9lyr`.

## 9. Локальное кэширование метаданных ⚡
- [x] **SQLite-кэш запросов:** *(Реализовано в `core/cache.py`)*
  - Кэширование сопоставлений ссылок, ISRC и данных об альбомах для предотвращения повторных внешних запросов к API.
  - Замер на живых API: **холодный проход 8 HTTP-запросов на трек (12.7 с), тёплый — 0 запросов (0.001 с)**.
- [x] **Ключи кэша — от точного к размытому:** `url` → `isrc` → `query`. Приоритет: точная ссылка побеждает ISRC, ISRC побеждает текстовый запрос.
  - `normalize_query` схлопывает эквивалентные формы: `Daft Punk - Get Lucky`, `daft  punk - get lucky`, `Daft Punk — Get Lucky`, `Get Lucky by Daft Punk`, `GET LUCKY DAFT PUNK` и `... (feat. Pharrell)` → один ключ.
  - `Get Lucky - Daft Punk` намеренно даёт **другой** ключ: это семантически другой трек.
- [x] **Раздельные ключи для обложек:** альбомный `(artist, album)` и релизный `release_id` — разные записи. Иначе альбомный результат перекрывает точный релизный (всплыло на тестах).
- [x] **TTL:** треки 30 дней, обложки 180 дней. Просроченные записи удаляются и при чтении, и через `prune()`.
- [x] **Кэш не является источником истины:** любая ошибка БД деградирует в «кэш пуст». Проверено на битом файле SQLite, на непроходимом пути и на несериализуемых значениях.
- [x] **Потокобезопасность:** соединение SQLite на поток + WAL для параллельных читателей (бот качает треки в потоках).
- [x] **Управление:** `CACHE_ENABLED`, `CACHE_PATH` в `.env`; `stats()`, `clear()`, `prune()`.

## 10. Кэширование уже скачанного в Telegram-боте (Instant Send via `file_id`) 🚀
- [x] **Кэш Telegram `file_id` (SQLite, `bot/fileid_cache.py`):** *(Реализовано)*
  - При успешной отправке сохраняется `message.audio.file_id` в локальную базу.
  - Ключи: `isrc:<ISRC>:<quality>` → `track:<norm artist - title>:<quality>` → `url:<sha1>:<quality>`.
  - **Качество обязательно входит в ключ:** FLAC и MP3 — разные файлы, отдавать MP3 вместо FLAC нельзя.
  - Нормализация переиспользуется из `core.cache`, чтобы «Daft Punk - Get Lucky» и «daft punk — get lucky» не заводили двух записей.
- [x] **Мгновенная отдача ранее скачанных треков:**
  - Повторный запрос отдаётся по `file_id` **до** скачивания: без поиска, без ffmpeg, без загрузки мегабайт в Telegram.
  - Ноль нагрузки на CPU и диск, защита от рейтлимитов Deezer / Soulseek / YouTube.
- [x] **Автоматическая инвалидация:** *(Реализовано)*
  - Telegram может в любой момент признать `file_id` недействительным (сменился токен бота, файл удалён).
  - `is_invalid_file_id_error` отличает протухший `file_id` от флуд-контрола и прочих ошибок: в первом случае запись удаляется и трек перекачивается, во втором — запись остаётся на месте.
- [x] **Живучесть кэша:** любая ошибка БД деградирует в «кэш пуст». Проверено на битом файле SQLite, непроходимом пути и конкурентной записи из 8 потоков.
- [x] **Управление:** `FILEID_CACHE_ENABLED`, `FILEID_CACHE_PATH`; `stats()`, `clear()`, `prune()`.
- [x] **Локальный кэш файлов в `DOWNLOAD_DIR` (для CLI):** *(Реализовано в `core/filecache.py`)*
  - Перед скачиванием проверяется наличие уже скачанного трека, чтобы не ходить по источникам повторно.
  - Индекс в SQLite (те же ключи, что у кэша метаданных: ISRC / нормализованное название / хеш ссылки), значение — путь и размер. Индекс переживает переименование файла и переезд папки.
  - Файлы лежат в `DOWNLOAD_DIR/.cache_audio/` под каноническим именем `Artist - Title.ext` (пометки версий и `feat.` из имени вычищаются).
  - Обрезанный или исчезнувший файл считается промахом, а не отдаётся пользователю.
  - Исходный файл в папке пользователя **не переносится** — делается копия.
  - CLI: `--force` (качать заново, минуя кэш), `--cache info` / `--cache clear`.
  - Бот кэш выключает (`reuse_cached_file=False`): файл живёт в `task_dir` и удаляется сразу после отправки, повторы отдаёт кэш `file_id`.
