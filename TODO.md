# Roadmap & TODO 📋

План развития и улучшений для **mus-downloader**.

---

## 1. Пакетная загрузка: Альбомы и Плейлисты
- [ ] **Парсинг ссылок на альбомы и плейлисты:**
  - YouTube / YouTube Music: `youtube.com/playlist?list=...`, `music.youtube.com/playlist?list=...`
  - Spotify: `open.spotify.com/album/...`, `open.spotify.com/playlist/...`
  - Apple Music: `music.apple.com/.../album/...`, `.../playlist/...`
  - Deezer: `deezer.com/album/...`, `deezer.com/playlist/...`
  - Яндекс.Музыка: `music.yandex.ru/album/...`, `.../users/.../playlists/...`
- [ ] **Очередь и параллелизм:**
  - Пакетное разворачивание ссылок в единую очередь треков с номерами (`track_number/track_total`).
  - Пул воркеров (`ThreadPoolExecutor`) для параллельной загрузки нескольких треков.
  - Красивый общий прогресс-бар пакета `[3/14] Скачивание: Artist - Title...`.
- [ ] **Загрузка из текстового файла (`--file` / `-i tracks.txt`):**
  - Чтение ссылок или названий треков построчно.
  - Пропуск уже скачанных файлов.
  - Итоговая статистика загрузки (успешно, пропущено, источники, затраченное время).
- [ ] **Генерация плейлистов:**
  - Создание файла `.m3u8` в папке альбома/плейлиста.

---

## 2. Улучшенный поиск и обработка обложек (High-Res Cover Art) 🎨
- [ ] **Каскадный поиск Ultra-HD обложек:**
  - Приоритет официальных квадратных обложек максимального разрешения (1400×1400 / 1000×1000) через iTunes Search API, Deezer API, Last.fm, MusicBrainz Cover Art Archive.
  - Поиск официальной альбомной обложки даже при скачивании по прямой ссылке на YouTube (замена превью видео на студийный арт).
- [ ] **Умная обработка YouTube Thumbnail:**
  - Если официальная обложка не найдена и берется превью из YouTube:
    - Автоматический выбор максимального разрешения (`maxresdefault.jpg` -> `hqdefault.jpg`).
    - Умный кроп соотношения 16:9 в квадрат 1:1 по центру без черных полос (letterboxing).
- [ ] **Сохранение обложки отдельным файлом:**
  - Опция сохранения `cover.jpg` / `folder.jpg` рядом с треками для плееров и медиасерверов (Plex, Navidrome, Jellyfin).

---

## 3. Режим «Оригинал без перекодирования» (Native Audio Stream) 🎚️
- [ ] **Сохранение исходных контейнеров (`--format original` / `-f opus|m4a|mp3|flac`):**
  - Для YouTube/SoundCloud: прямое извлечение исходного потока Opus (~160 kbps) или AAC (~128 kbps) без пережатия ffmpeg.
  - Защита от **generational loss** (потери качества при повторном lossy-to-lossy сжатии Opus -> MP3).
  - Экономия ресурсов процессора и ускорение скачивания треков.
- [ ] **Нативное тегирование оригинальных контейнеров:**
  - Полноценная запись метаданных и вшивание обложек в `.opus` (через Mutagen OggOpus) и `.m4a` (через Mutagen MP4).

---

## 4. Тексты песен и караоке (Lyrics & Synced LRC) 📝
- [ ] **Интеграция с [LRCLIB](https://lrclib.net/):**
  - Публичный бесплатный API, не требующий API-ключей.
  - Поиск по `artist_name`, `track_name`, `album_name` и `duration`.
- [ ] **Караоке `.lrc` файлы:**
  - Сохранение синхронизированных субтитров рядом с аудиофайлом (`Artist - Title.lrc`) для плееров с караоке (Poweramp, Retro Music, AIMP, Symfonium).
- [ ] **Вшивание в теги:**
  - ID3v2 (MP3): фреймы `USLT` (Unsynchronized lyrics) и `SYLT` (Synchronized lyrics).
  - FLAC / Vorbis Comments: поля `LYRICS` и `UNSYNCEDLYRICS`.
  - MP4 / M4A: тег `\xa9lyr`.

- [x] **Интеграция поиска и настроек в Telegram-бота:**

  - Интерактивные кнопки выбора трека `[ 1 ] [ 2 ] ... [ ❌ Отмена ]` с мгновенным стартом скачивания при настроенном качестве. *(Реализовано)*
  - Выбор режима поиска по умолчанию в `/settings` (🎯 Сразу лучший / 📋 Список вариантов). *(Реализовано)*

  - Отображение анимированного спиннера, шкалы прогресса, скачанных/общих МБ, текущей скорости (МБ/с) и оставшегося времени (ETA). *(Реализовано)*
  - Сквозная передача прогресса для Deezer (стриминг chunk-by-chunk), YouTube / YouTube Music (`yt-dlp` progress_hooks), Soulseek (bytes_transferred), SoundCloud и прямого скачивания (VK CDN). *(Реализовано)*
  - Отдельные этапы: поиск метаданных, скачивание потока, ffmpeg-конвертация и вшивание тегов/обложки. *(Реализовано)*

## 10. Кэширование уже скачанного в Telegram-боте (Instant Send via `file_id`) 🚀
- [ ] **Кэш Telegram `file_id` (база данных SQLite):**
  - При успешной отправке аудиофайла ботом сохранять возвращенный `message.audio.file_id` в локальную базу данных (SQLite).
  - Ключи кэширования:
    - По ISRC: `(isrc, quality)` (наивысшая точность для официальных треков).
    - По нормализованному названию: `(norm_artist_title, quality)`.
    - По ссылке-источнику: `(url_hash, quality)`.
- [ ] **Мгновенная отдача ранее скачанных треков:**
  - При повторном запросе того же трека любым пользователем — отправлять аудио по сохраненному `file_id` (`bot.send_audio(audio=cached_file_id)`) за 0.1 секунды.
  - Полное исключение повторного поиска, скачивания, перекодирования ffmpeg и повторной загрузки десятков мегабайт в Telegram.
  - Нулевая нагрузка на CPU и диск, экономия трафика сервера и защита от рейтлимитов источников (Soulseek / Deezer / YouTube).
- [ ] **Автоматическая инвалидация и обработка ошибок:**
  - Если Telegram возвращает ошибку недействительного `file_id` (удален на серверах Telegram или сменился токен бота) — автоматическое удаление записи из кэша и прозрачный переход к стандартному скачиванию с обновлением кэша.
- [ ] **Локальный кэш файлов в `DOWNLOAD_DIR` (для CLI и бота):**
  - Проверка наличия уже скачанного трека на диске перед запуском процесса загрузки (по имени файла или хешу метаданных).
